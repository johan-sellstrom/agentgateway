# HAPS-guarded agentgateway on Google Cloud (lab)

This directory deploys agentgateway, with the `haps-guard` mcpGuardrails processor, to Cloud Run in
project `lab-mcp-johan`, region `europe-west2`. Every service is private: the gateway accepts only
callers with IAM `run.invoker`. The guard and the demo MCP server use internal ingress and accept
only the gateway's service account.

The trust anchors are **test fixtures**. The test Presence Provider and the test certifier are keys
generated by `haps-mint init`, not iProov's. See [Swapping in real trust anchors](#swapping-in-real-trust-anchors).

## Architecture

```
 caller (gcloud identity token)
   │  HTTPS, Cloud Run IAM (run.invoker), else 403
   ▼
 haps-gateway        Cloud Run, ingress all, --no-allow-unauthenticated
 (agentgateway)      SA haps-gateway@ ; Direct VPC egress (all traffic) via subnet haps-run
   │                 (Private Google Access, so the gateway reaches *.run.app over the VPC
   │                  and internal-ingress services accept the calls)
   ├── gRPC over TLS, Google ID token (backendAuth gcp idToken, aud = guard URL)
   │     ▼
   │   haps-guard    Cloud Run, ingress internal, IAM-only, --use-http2 (h2c to the container)
   │     │           SA haps-guard@ ; Direct VPC egress (private ranges) via haps-run
   │     ▼
   │   Memorystore for Redis  haps-guard-state: Basic, 1 GB, AUTH on, private IP on `default`
   │                           (replay store, challenges, spend-on-success reservations)
   │
   └── MCP Streamable HTTP over TLS, Google ID token (aud = demo URL)
         ▼
       haps-demo-mcp  Cloud Run, ingress internal, IAM-only. Tools: echo (ungated),
                      transfer (payment.transfer), rotate_key (admin.rotate_key),
                      inspect_meta (demo.inspect_meta)
```

The gateway runs the guard on `tools/call`, on both phases: the request side verifies and spends the
approval, and the response side settles `spendOn: success`. The CEL metadata
`hapsReservation: mcpGuardrails.haps.reservation` carries the reservation id from the first phase to
the second.

Guard policy (`config/haps-guard.yaml.tmpl`):

| tool | action type | binding | mode |
|---|---|---|---|
| `transfer` | `payment.transfer` | exact | agent-initiated, spent on forward |
| `rotate_key` | `admin.rotate_key` | exact | `challengeMode: true`, `spendOn: success` |
| `inspect_meta` | `demo.inspect_meta` | exact | agent-initiated. Shows the credential is stripped from `_meta` |
| `echo` | n/a | n/a | not gated |

### How the gateway authenticates to the guard and the upstream

agentgateway's `backendAuth.gcp` (`type: idToken`) attaches a Google ID token for its service
account, from the metadata server, to every request it makes to a backend. That includes the
guardrail's gRPC channel, because `mcpGuardrails.processors[].policies` takes the same backend
policies. That is the strongest option available, so the lab uses it on both hops, and it adds to
network restriction rather than replacing it:

- **Guard**: internal ingress. IAM-only, with `run.invoker` granted only to `haps-gateway@`.
- **Demo upstream**: internal ingress. IAM-only, with `run.invoker` granted only to `haps-gateway@`.
- **Gateway**: public ingress, IAM-only. Cloud Run checks the caller's identity token before the
  request reaches agentgateway.

No Rust code changed to deploy. The only Rust-side change is a `[[example]]` entry in
`crates/haps-guard/Cargo.toml` that points at `deploy/gcp/mint/haps_mint.rs`.

## Where secrets live

| secret | content | who can read it |
|---|---|---|
| `haps-test-pp-private-key` | Test Presence Provider Ed25519 key (PKCS#8 PEM) | project owners only. No service account |
| `haps-test-certifier-private-key` | Test certifier Ed25519 key | project owners only. No service account |
| `haps-guard-config` | Rendered guard config. Contains the Memorystore AUTH string in the Redis URL | `haps-guard@` |
| `haps-trust-pp-jwks`, `haps-trust-certifier-jwks`, `haps-trust-pcc` | Public trust anchors, mounted as files | `haps-guard@` |
| `haps-gateway-config` | Rendered gateway config (no secrets; Secret Manager is used as a file mount) | `haps-gateway@` |

Local copies of the private keys sit in `deploy/gcp/.secrets/`, which is gitignored. `mint.sh` fetches
the Presence Provider key from Secret Manager if the local copy is missing. The certifier key is only
needed to re-sign the PCC.

## Deploy

```sh
export PATH=/Users/johansellstrom/bin/google-cloud-sdk/bin:$PATH
deploy/gcp/deploy.sh                 # about 15 min, mostly the Rust build
SKIP_BUILD=1 TAG=<tag> deploy/gcp/deploy.sh   # redeploy existing images / config changes
```

`TAG` defaults to the short git SHA of `HEAD`. Set `GCLOUD=/path/to/gcloud` if gcloud is not on `PATH`.
On a first deploy, the gateway's new `run.invoker` grants can take a minute to propagate. Until then
the gateway's upstream calls fail with `mcp: upstream error: 403`. If `trust/mint.json` is missing, the first run generates
the trust anchors with `cargo run -p haps-guard --example haps-mint -- init`.

## Call it

```sh
URL=$(gcloud run services describe haps-gateway --region europe-west2 --format 'value(status.url)')/mcp
TOKEN=$(gcloud auth print-identity-token)
H=(-H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream')

curl -s "$URL" "${H[@]}" -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'

# Gated, no approval: JSON-RPC error -32042 with an elicitation URL
curl -s "$URL" "${H[@]}" -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"transfer","arguments":{"amount":"250.00","currency":"GBP","payee":"Example Supplier Ltd"}}}'

# Approved: mint an approval for exactly these arguments, then send it
deploy/gcp/mint.sh approve --tool transfer --action-type payment.transfer \
  --args '{"amount":"250.00","currency":"GBP","payee":"Example Supplier Ltd"}' > approved.json
curl -s "$URL" "${H[@]}" --data-binary @approved.json

# Challenge mode: save the -32042 response, answer its challenge
curl -s "$URL" "${H[@]}" -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"rotate_key","arguments":{"keyId":"signing-key-1"}}}' > challenge.json
deploy/gcp/mint.sh approve --tool rotate_key --challenge challenge.json > answer.json
curl -s "$URL" "${H[@]}" --data-binary @answer.json
```

Amounts are strings. HAPS canonicalisation rejects fractional numbers. `deploy/gcp/verify.sh` runs the
full sequence: 403 without a token, list, ungated, -32042, approved, tampered, replayed, challenge
issued, answered, answered again, and the credential stripped from `_meta`.

Your own account needs `roles/run.invoker` on `haps-gateway`. Project owners have it already. To let
another person call the gateway:
`gcloud run services add-iam-policy-binding haps-gateway --region europe-west2 --member user:NAME@iproov.com --role roles/run.invoker`.

## Lab limitations

- **Basic-tier Memorystore has no replica**, so `minReplicaAcks` stays `0`. If the node fails, the
  replay and challenge state is lost, and an approval spent before the failure could be accepted
  again. Production needs Standard tier, or Memorystore Cluster, with `minReplicaAcks: 1`.
- **No TLS to Redis.** The guard's `redis` crate is built without TLS, so in-transit encryption is
  off. AUTH is on, which guards against accidental access but not against an attacker on the VPC.
  Traffic stays on the private VPC.
- **Test trust anchors.** Anyone with the test Presence Provider private key can approve anything.
  The PCC's `evaluation` is labelled as a test fixture. `elicitationUrl` points at `*.invalid`, and
  no Presence Provider exists in this deployment: the `-32042` URL only shows the flow.
- **No rpSigningKey.** Challenges are not signed (`rpProof` absent).
- **Gateway build.** The image is built without the admin UI, because the UI's `pnpm build` fails
  type checking at this commit. The UI is only on the container's localhost admin port in any case.
  It uses the `quick-release` profile (no LTO) to keep the build to minutes.
- **Single region, no custom domain, no Cloud Armor, no audit export** of the guard's decisions,
  beyond Cloud Logging.
- **Gateway clients are not individually authenticated by agentgateway.** Cloud Run IAM is the only
  caller check, and agentgateway does not see who called. Add `mcpAuthentication` if per-caller
  policy is needed.

## Swapping in real trust anchors

1. Put the real Presence Provider issuer and its JWKS in `issuers`, the real certifier and its JWKS
   in `certification.certifiers`, and `certification.providers[issuer] = providerId` in
   `config/haps-guard.yaml.tmpl`. Replace or add the matching `haps-trust-*` secrets and mounts in
   `deploy.sh`.
2. Embedded PCCs need nothing else. For referenced PCCs, provision them under
   `certification.provisioned`.
3. Set `elicitationUrl` to the Presence Provider's approval URL.
4. Re-run `SKIP_BUILD=1 deploy/gcp/deploy.sh`.
